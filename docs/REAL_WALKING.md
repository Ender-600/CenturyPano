# 真实行走与手机视角

生成后端、Google 历史全景流程和 Spark 三维显示继续使用原有代码。已加载的生成世界支持两种真实行走输入：`mobile/ios` 与 `mobile/android` 原生客户端用 ARKit／ARCore 的视觉惯性追踪获取位置和朝向；普通 Safari／Chrome 可用 GPS 经度、纬度变化近似跟随室外步行，并继续独立使用方向传感器转动视角。页面默认使用 GPS 行走与独立的手机方向跟随；原生 AR 追踪可在设置中明确选择。

GPS 适合室外、定位较好的场景，不能提供 AR 的细小位移追踪。浏览器定位可能来自 GPS 或网络，`watchPosition` 不承诺固定更新频率；请求高精度也不保证得到高精度。页面显示定位精度和跟随状态，实际延迟与误差需要真机测量。[W3C Geolocation](https://www.w3.org/TR/geolocation/)

## 竖屏环顾

Safari 的 `webkitCompassHeading` 只用于建立一次北向参照，且要求手机接近水平、精度有效。之后保持固定的北向偏移，使用完整的 `alpha/beta/gamma` 相对姿态四元数跟随俯仰、左右转头和倾斜，不再每帧用指南针覆盖姿态角。优先使用相对方向事件；只有绝对方向事件的设备仍依赖其系统融合，不能保证完全消除磁场干扰。[W3C 方向事件](https://www.w3.org/TR/orientation-event/#choice-of-reference-coordinate-system)

方向跟随默认开启。无需权限弹窗的浏览器自动启动；iOS 在首次点击页面时同步请求系统运动权限，已授权会话返回前台时自动恢复。没有独立的 Pause motion 流程，三种视图及方向控制都放在右上角设置内。无传感器或权限未获准时保留拖动回退。

若暂时没有北向参照，先按相对姿态跟随；第一次获得可靠指南针数据时自动对齐真实方位。在 Safari 中可能需要短暂把手机放平、屏幕朝上，再竖起。**Align with compass** 只接受点击后新取得的可靠指南针读数；不会把拖拽后的画面、GPS 行进方向或相对 alpha 当作北向。对齐完成后继续使用固定北向参照加姿态变化；后续指南针跳动不会不断改写画面。切换源街景、历史全景和生成世界保留方向跟随。

## 坐标与距离

原生包输出右手、+Y 向上、以米为单位的位置，以及按屏幕方向校正的后摄朝向。首个可靠帧记录现实起点；当前虚拟相机位置是虚拟起点。只校准水平朝向，使重力方向保持一致。

```
虚拟位置 = 虚拟起点 + 模型单位/米 × 朝向校准旋转 ×（当前真实位置 − 真实起点）
虚拟朝向 = 朝向校准旋转 × 当前后摄朝向
```

GPS 模式把相对起点的经纬度变化换算为东、北方向的米制水平位移，再通过固定的水平朝向映射到世界；保持当前相机高度。自动启动时配对同一传感器样本的真实镜头朝向与虚拟朝向，避免把相机插值延迟带入位移映射。源街景和历史全景使用源图的 heading 旋转球面；生成世界在米制处理和 X180 坐标转换之外再施加 Y−heading。该生成世界的朝向继承是估算，提供方没有保证生成几何与输入全景精确配准；指南针本身也可能有磁偏角和干扰。

两种模式的位移都不沿手机当前视线累加。因此原地转手机不平移，边向前走边侧看时位置仍沿真实行进方向变化。GPS 只控制平移，手机俯仰、倾斜和转动继续由现有方向跟随控制；GPS 的行进 `heading` 不作为镜头朝向。每帧在手机本地渲染，不会重新调用图像生成或 Marble。

若查看器已应用提供方米制比例，移动使用每米一个场景单位；比例与地面高度独立处理，有有效比例但无地面高度时仍可按米移动，界面标明地面高度未校准。这仍不证明 AI 世界和现场地物完全一致。GPS 模式缺少尺度元数据时默认估算为每米一个场景单位，设置明确标注估算；用户可以暂停行走后指定比例，或在三维场景中选两个点、输入这两点的真实间距。原生 AR 模式仍要求有效比例。两点测量直接使用 Spark 对实际 splats 的光线求交，取点失败不会猜测深度。手动测量只能校准统一比例，无法修复生成几何的局部形变，也不能自动找回历史建筑的绝对地理位置。

## 运行流程

1. 用手机 Safari／Chrome 或已安装的 CenturyPano 原生客户端打开 HTTPS 演示链接。独立演示访问码可以放在原有 `#access=` 片段中，不需要把服务商密钥写进手机工程。
2. 允许定位；首次点击页面时允许系统运动权限。三种视图与指南针对齐按钮在右上角设置里，画面中央没有步行设置提示。必要时短暂放平手机以获得可靠北向，再竖起环顾。
3. 生成世界加载且镜头方位可靠后自动启动 GPS 跟随；获得精度合适的新定位后建立起点。全景照片本身只支持环视；沿道路切换拍摄点使用单独的预生成功能。
4. GPS 暂时变差时保持当前位置。超时、跳点或返回前台后，等待两次至少间隔 1 秒的新鲜可靠定位，从当前显示位置自动恢复；不补走后台路程，也不跳到失联期间的位置。拒绝定位权限或明确点击 Stop 后不会自动重试。
5. 重新按指南针对齐时保留当前位置，等待新的北向后自动建立 GPS 方向映射。正常转动手机或尝试拖拽不会停止行走或改变北向。切换生成世界自动建立新起点；三维跟随期间不会自动换世界。
6. 另外开启 **Prepare ahead as you walk** 后，可在后台准备前方历史全景，并在全景视图到点切换；这不提交新的三维世界生成，详见 [预测步行](PREDICTIVE_WALKING.md)。原生 AR 跟随仍为设置中的明确选择，使用相机权限和 ARKit/ARCore。

GPS 的移动阈值为 `max(1.5 米, 0.35 × (上次移动目标精度 + 新定位精度))`。例如精度均为 ±10 米时，约需累计 7 米的位置变化才更新目标；小步会累积，但也可能被噪声覆盖。画面显示当前精度、距离起点的位移，以及「已观测位移 / 移动阈值」，帮助区分未启用、等待定位和未超过阈值。不会通过降低噪声阈值或沿视线猜测步幅伪造精确行走。

GPS 默认启动；设置中的 Stop 会保持暂停，Resume GPS walking 恢复。原生相机仅在明确选择并启用 AR 模式后使用。GPS 和原生空间追踪不能同时驱动位置；GPS 不使用加速度双积分或步数猜测距离，不承诺逐步、厘米级或室内实时定位。

## 验收边界

- 手机视口 390 × 844 已检查主画面与设置布局；自动化测试覆盖指南针初始对齐、重新对齐、连续方向跟随、首次授权与前后台恢复。实体 iPhone 传感器和现场地标配准仍需实测。
- 本地数学与模拟事件测试可验证米制位移的比例换算、GPS 东北方向映射、侧看时的独立平移、纯转动、定位质量筛选、重设起点、陈旧／乱序数据丢弃，以及失跟冻结。
- 模拟器可以检查网页加载、桥接、设置与不支持 AR 的提示，不能证明真实摄像头追踪精度。
- 实体手机验收仍待完成。GPS 需要在开阔室外检查静止漂移、已知距离往返、侧向与后退行走、指南针对齐、定位变差和后台恢复，记录延迟与距离误差。AR 需要在有纹理、光线正常的小范围现场试走，检查前进和后退、原地转动、边走边侧看、横竖屏、遮住摄像头、切到后台和重新开始。
- 生成场景的可用范围和历史几何可能与现场不同；不把生成模型的碰撞面当成现实障碍物。此版本只映射位姿，不保证建筑逐像素对齐或长距离无漂移。
