# 四种时间旅行模式

应用主入口 `/` 统一采用全屏无边界视窗界面。顶部导航为悬浮毛玻璃，场景延伸至屏幕边缘和导航后方；四个 Tab 的顺序固定：

| 模式 | 输入与显示内容 | 生成方式 |
| --- | --- | --- |
| 全景相机 | 默认入口；拍摄当前位置或选择手机里的全景照片 | 拍摄或上传完成后进入第二个 Tab 预览 |
| 照片历史全景 | 用户拍摄／上传的原图与生成结果 | 点击生成后运行照片流水线；保留天气、热点说明、今昔对比、下载和地图档案 |
| Street View 历史全景 | 当前地点的 Google Street View 360° 街景及其历史改图 | 明确点击后只生成历史全景图片，不要求先生成 Marble 世界 |
| Marble 沉浸世界 | 相同街景地点对应的三维世界 | 明确点击后生成世界；相同输入可复用已有历史全景，并保留行走功能 |

Google 街景原图属于第三个模式内的“现在”视图，不是第一个模式的相机输入。

## 年份、地点和结果

四个模式共享一个目标年份，默认 **1926**。滚轮支持逐年选择、触摸滚动、鼠标与键盘操作。选择年份或切换 Tab 不会自动提交生成；已生成图像始终保留实际生成年份，不能把旧结果重新标成新年份。

照片拍摄位置与手机当前位置可能不同。照片继续使用原有的手填地点／EXIF／设备定位规则；Street View 和 Marble 共用同一个街景计划，单纯切换模式不会把照片坐标当成当前 GPS，也不会重新生成。

拍摄或上传后自动进入照片历史全景模式。返回相机模式不丢失照片模式的进行中任务和已完成结果。照片地图档案和世界任务保留各自原来的存储格式与访问边界，旧照片回放和世界分享链接继续可用。

## 历史重建规则

所有历史生成默认允许根据年份和地点背景改变建筑轮廓、高度、道路与地块用途，同时保持观察位置、方向和全景投影一致。照片流水线的 `STRUCTURE_LOCK` 默认值为 `0`；已有环境若明确设置为 `1`，应改为 `0` 并重启以使用本次默认产品规则。原来的锁定结构代码仍可作为显式实验设置使用。

历史建筑变化是模型推断，界面继续保留不确定性说明。照片瓦片仍共享历史上下文并使用拼接处理，Street View 全景仍在完整 360° 图像上编辑。

## 模式生命周期

照片与相机使用主应用的交互流程。Street View 和 Marble 复用一个延迟加载的同源查看器；只在首次进入相关 Tab 时启动。父子页面校验消息来源窗口和同源 origin，然后同步当前模式、激活状态及目标年份。

离开模式时暂停相机、方向传感器、GPS 跟随、渲染和未提交的预测准备；已提交的生成任务可以继续完成，保留状态轮询与结果。后台任务完成不会强制切换用户正在浏览的 Tab。付费全景行走仍需要用户明确开启。

`/world/` 保留独立查看器入口，兼容原生客户端和原有仅世界模式的分享代理。完整四模式应用应打开主服务的 `/`。原有 `serve_world_access.py`、`serve_world_lan.py` 和只读分享代理继续限制为世界相关接口，不能把它们的链接当成完整应用入口。

## 运行与验证

先运行 `uv sync --python 3.11` 和 `npm ci`，再启动主 FastAPI 服务。Three.js 与 Spark 由 `/world-vendor/` 从本机依赖提供。Docker 构建包含这两个依赖，照片与世界数据分别保存在 `/data/in`、`/data/out`、`/data/worlds`。

照片使用 `PROVIDER` 指定的提供方；Street View 历史全景使用 OpenAI 图片编辑，Marble 世界另外使用 World Labs。世界全景使用单独的 `WORLD_OPENAI_IMAGE_MODEL` 设置，以免改变照片提供方默认配置；访问码与服务商密钥留在既有鉴权流程中。

自动化验证覆盖四 Tab 切换、默认年份与同步、上传后的跳转、任务结果保留、错来源消息拒绝、隐藏模式不启动传感器或准备、第三模式只生成图片、第四模式生成世界，以及照片与世界两套 API 的回归测试。浏览器验收还应检查窄屏顶部导航、滚轮、设置面板与旧分享链接。模拟测试不代替实体手机上的 GPS、相机和 GPU 验收。
