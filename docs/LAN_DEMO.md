# 同一 Wi-Fi 的 HTTP 演示入口

手机和电脑连接同一 Wi-Fi 时，可运行独立的内网入口，让页面自动连接现有后端，无需手动输入访问码。世界生成仍由原有服务负责，内网入口不会启动第二个生成任务管理器。

先保持原有后端（例如 `127.0.0.1:8001`）运行，再使用电脑当前 Wi-Fi IPv4 地址与实际子网启动：

```bash
.venv/bin/python scripts/serve_world_lan.py \
  --host 172.26.43.152 --port 8002 --network 172.26.0.0/17 \
  --upstream http://127.0.0.1:8001
```

手机打开 `http://172.26.43.152:8002/world/`。换 Wi-Fi 或电脑 IP 变化后，需要使用新地址、子网重新启动。电脑与两个服务需保持运行；Wi-Fi 若启用了客户端隔离，即使同一网络也可能无法互访。

入口只监听明确指定的内网地址，并校验连接来源与 Host。它提供独立的临时内网会话，在本机代为连接已有后端；不会把原后端的访问码放进页面或链接，也不会改变现有公网入口。处于允许子网内、能连接此入口的设备可以访问页面和生成服务，因此只在你允许同网设备使用后端时启动。

浏览器通常不会在普通 HTTP 内网地址开放定位和方向传感器。此入口可查看已有世界、拖动浏览、使用明确输入的测试坐标调用后端；真实 GPS 行走与手机转动跟随仍需受信任的 HTTPS 页面。使用 `?world=已保存任务ID` 可以直接载入一个已有世界，不触发重新生成。

## 手机传感器的 HTTPS 演示

要在手机浏览器启用 GPS 和方向传感器，可以为一个已生成世界运行单独的 HTTPS 查看入口：

```bash
.venv/bin/python scripts/serve_world_viewer.py \
  --world d6f1a244b43d4a590bd180c9f793f508 --port 8003 \
  --upstream http://127.0.0.1:8001
cloudflared tunnel --url http://127.0.0.1:8003 --protocol http2
```

使用隧道给出的 HTTPS 域名，打开 `/world/?viewer=1&world=d6f1a244b43d4a590bd180c9f793f508`。此入口公开所选世界及其显示资源，不需要手动访问码；原后端的访问码仅保存在本机。入口不允许创建、更改或恢复生成任务，也不能读取其他世界。

在手机 Safari／Chrome 中打开链接，等待世界加载，点 **Enable motion** 并允许系统方向权限。GPS 行走仍在设置中启用，先检查比例与实际朝向。HTTPS 让浏览器可以请求传感器权限，但不能替用户点击系统权限弹窗；真实追踪精度仍取决于设备和环境。
